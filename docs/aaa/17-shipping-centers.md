## 2. 한국 → 일본 국제배송비(무게 구간표)

- 금액 = CarryToJ 해상특송 ACE 원가 × 가산율 1.10, 10원 단위 올림. 실무게·부피무게(가로×세로×높이 cm ÷ 6000) 중 큰 값 기준.
- 원가는 `intl_ship_rates`, 가산율은 `intl_ship_settings`. 두 표는 운영자만 읽는다(RLS). 고객·판매자는 함수로 최종 금액만 받는다(`intl_ship_fee_krw`·`intl_ship_bands`·`listing_quote`).
- 운영자 수정: tomo 어드민 `/admin/center` 맨 위 「한국→일본 국제배송 요율」(원가 칸·가산율 칸). 새로 여는 결제부터 적용되고 이미 만든 거래 금액은 바뀌지 않는다. 고객센터 FAQ·llms.txt 의 예시 금액(1kg 9,260원)은 코드 문구라 요율을 바꾸면 같이 고친다.
- 결제 금액은 서버가 정한다: `start_transaction`·`start_auction_transaction`(DB)이 `direct_intl_fee` 를 부르고, 상세 화면 총액·경매 입찰 패널은 같은 함수에서 나온 `listing_quote` 를 쓴다.
- 일본 → 한국(¥900 정액)과 해외 마켓 구매대행 정액(₩8,000/¥900)은 바꾸지 않았다.

### 판매자 무게 입력
- 한국 판매자가 국제 거래를 켜고 택배(또는 둘 다)를 고르면 판매 폼에 「포장 후 무게」가 나온다(필수). 버튼: 0.5·1·2·3·5·10kg 이하, 「그 이상(직접 입력)」 최대 17kg. 버튼마다 고객 금액이 보인다. 부피가 큰 물건 안내 문구, 실측 초과 시 정산 차감 고지가 같이 보인다.
- DB 트리거 `listings_require_weight`: 한국 상품을 국제 택배로 새로 열 때(등록·국제 거래 켜기·택배 켜기·무게 지우기) 무게가 없으면 저장이 거절된다. 값이 그대로인 갱신(상태 변경 등)은 막지 않는다.
- 기존 상품(무게 없음) 규칙: **국제 결제를 무게 입력 전까지 막는다.** 상세 화면은 해외 구매자에게 「판매자가 포장 무게를 입력하면 해외에서도 살 수 있어요」를 보이고 결제 버튼을 내지 않는다. 같은 나라 구매자의 국내 거래는 그대로 된다. 근거: 적용 시점(2026-11-28) 공개 판매 중인 한국 국제 거래 상품 0건(한국 상품 4건 = 판매완료 2·숨김 2), 진행 중 국제 거래 0건. 기본 1kg 으로 받는 안은 무거운 상품에서 판매자 차감이 커져 분쟁이 생길 수 있어 고르지 않았다.

### 실측 무게가 더 무거울 때
- 한국 센터 입고 뒤 운영자가 실측 무게를 넣는다(tomo `/admin/center` 거래 줄 「실측 저장」, 운영 API `POST /api/ops/trades/:id/measured_weight` {kg}). 상태가 센터로 발송·센터 입고일 때만 된다.
- 실측 구간 금액 − 결제된 국제배송비 = 차액. 차액은 `transactions.ship_overage` 에 적히고 거래 완료 때 판매자 정산(seller_ledger sale 행)에서 빠진다(판매자 몫 상한, 메모 「실측 무게 초과 배송비 N 차감」). 판매자에게 알림 `tx_ship_overage`. 가벼우면 0(돌려주지 않음, 구매자 추가 청구 없음).
- `admin_adjust_seller_ledger` 를 쓰지 않은 이유: 센터 단계에서는 판매 대금이 아직 적립 전이라 잔액이 0 이고, 음수 잔액 금지 규칙에 걸려 차감이 거절된다. 그래서 적립 때 빼는 방식으로 했다.

## 3. 통관 예치금(한국 → 일본 직거래)

- 상품가 × KRW_JPY 환율 ≥ ¥16,666 이면 상품가의 10%(10원 단위 올림)를 결제에 포함(`transactions.customs_deposit`). 기준 원화 = `customs_min_krw()` = ceil(16666 ÷ 환율). 환율이 없으면 결제를 막는다.
- 결제 합계 = 상품가 + 국제배송비 + 통관 예치금(`tx_charge_base`). 결제창 금액·결제 확정 대조(stripe-settle)·환불 비율 분모(lib/refunds.ts)가 같은 합계를 쓴다.
- 판매자 정산·수수료(10%)에는 넣지 않는다(에스크로 보관분).
- 고객 화면: 상세·경매 패널·거래 화면에 「통관 예치금(실제 세금과 정산, 남으면 환불)」 줄. ¥16,666 미만이면 가죽 신발·니트 안내 문구만.
- 정산: 운영자가 실제 관부가세(거래 통화 = 원)를 넣는다(tomo `/admin/center` 거래 줄, 운영 API `POST /api/ops/trades/:id/customs_settle` {actual, memo}). 국제 발송 뒤(shipped_international·delivered·completed·disputed)에만 된다.
  - 남으면: 부분 환불 행(refunds, is_full=false)을 만들고 바로 실행한다. 실패하면 `/admin/refunds` 대기열에 남는다. Stripe 금액은 실제 청구 원화 비율로 계산된다.
  - 모자라면: `customs_shortfall` 에 운영 부담으로 기록한다. **추가 청구 경로는 만들지 않았다.**
  - 한 거래에 통관 정산 부분 환불 1건 + 전액 환불 1건(취소·분쟁)까지. 전액 환불 금액은 결제 합계 − 이미 잡힌 환불(`tx_refundable`).
- 일본 → 한국 방향은 이번 범위 밖.

## 4. 센터 접수 번호(결제 뒤 운영자가 하는 일)

국제 직거래가 결제되면 `tx_center_steps` 에 한 줄이 생기고 운영 알림 `center.step_due` 가 에어쉽으로 간다. 6시간 안에 번호가 없으면 `center.step_overdue` 를 한 번 더 보낸다(크론 `tomo_center_steps`, 매시 7분). 운영 API counts 에 「배송대행 신청 필요(CarryToJ)」「입고 예정 등록 필요(재팬비즈)」 두 줄. 메모는 운영자만 읽는다.

### 4.1 한국 센터 — CarryToJ 배송대행 신청 (Ren 이 따라 할 절차)

주의: 4~6단계 CarryToJ 신청서 칸 이름은 화면을 직접 열어 보지 않고 쓴 것이다(추정). 첫 신청 때 실제 칸 이름으로 고친다.
1. 에어쉽 어드민 → 연결 사이트 TOMO → 센터 → 「센터 접수 필요」 탭을 연다(또는 tomo `/admin/center`).
2. 거래 번호(TX…)와 상품명을 확인한다.
3. carrytoj.com 에 몽상앤코 계정으로 로그인한다.
4. 배송대행 신청서를 새로 쓴다. 운송 방법은 해상특송(ACE 요율 기준)을 고른다.
5. 신청서에 판매자 국내 송장(거래에 적히면), 상품명, 수량, 신고 금액(상품가)을 적는다. 메모 칸에 거래 번호(TX…)를 적는다.
6. 받는 사람은 그 거래의 일본 구매자 배송지로 적는다.
7. 신청서를 저장하고 신청번호를 복사한다.
8. 연결 화면(또는 tomo 어드민) 「CarryToJ 신청번호」 칸에 넣고 「완료 표시」를 누른다. 메모는 운영자만 본다.
- 판매자는 결제 직후부터 CarryToJ 주소로 보낸다. 받는 사람 = 「몽상앤코 (TX000123)」, 주소 끝의 코드 CA-0816 은 그대로. 코드 뒤에 글자를 붙여도 CarryToJ 가 받는지 확인되지 않아 코드 칸은 건드리지 않았다.
- 입고 뒤 CarryToJ 가 무게를 확정하면 「실측 저장」에 그 무게를 넣는다(차액은 판매자 정산에서 빠진다).

### 4.2 일본 센터 — 재팬비즈 입고 예정 등록
1. 「입고 예정 등록 필요(재팬비즈)」 줄의 거래를 연다.
2. japanbiz.kr 에 로그인해 입고 예정 등록 화면을 연다.
3. 구매한 쇼핑몰 = TOMO, 품목, 상품명, 수량, 단가(엔)를 적고 「입고 예정 등록」을 누른다.
4. 목록에 뜬 신청서 번호를 복사한다.
5. 연결 화면(또는 tomo 어드민) 「재팬비즈 입고 예정 신청서 번호」 칸에 넣고 저장한다.
- 저장하는 순간 판매자 거래 화면의 주소가 「千葉県富里市七栄649-114 建物内109 <번호>」로 완성되고 판매자에게 알림 `tx_center_addr_ready` 가 간다. 저장 전에는 판매자에게 「센터 주소를 준비하고 있어요 — 알림이 오기 전에는 보내지 마세요」만 보인다.
- 센터 화면 검색은 거래 번호(TX…)와 이 신청서 번호 둘 다 된다.

## 5. 운영 API (docs/aaa/12 9장)
| 경로 | 권한 | 내용 |
|---|---|---|
| `GET trades?step=open` | ops | 센터 접수 번호가 없는 결제 완료 건 |
| `GET trades?customs=open` | ops | 통관 정산이 남은 건 |
| `GET trades?q=<신청서 번호>` | ops | CarryToJ·재팬비즈 번호로 찾기 |
| `POST trades/:id/center_step` {ref, memo, expected_status} | ops | 번호 넣기·고치기 |
| `POST trades/:id/measured_weight` {kg, expected_status} | money | 한국 센터 실측 |
| `POST trades/:id/customs_settle` {actual, memo, expected_status} | money | 통관 정산(+부분 환불 실행) |

거래 행(TX_COLS)에 `customs_deposit, customs_actual, customs_shortfall, customs_settled_at, ship_weight_kg, measured_weight_kg, ship_overage, center_step{ref, memo, done_at, due_at}` 가 붙는다. 이벤트 `center.step_due`·`center.step_overdue`.
