# 결제 점검표 (T4, 01#2)

결제·주문 금액 코드를 바꾼 뒤 이 순서로 확인한다. 먼저 Stripe 테스트 모드로 한다. 운영 실결제는 Ren이 정한 경우에만 한다(05-roadmap 9절 3번).

## 0. 준비

1. 0035를 `begin … rollback`으로 시험한다(파일 끝 확인 쿼리).
2. 0035를 적용한다. 그다음 코드를 병합한다.
3. DB 테스트를 돌린다: `tests/price-check.db.test.ts`, `tests/cart-rls.test.ts`, `tests/escrow.test.ts`.
4. 시험 계정은 한국 거주 1개, 일본 거주 1개를 쓴다.

## 1. 장바구니 주문: 가격이 그대로인 경우

1. 메루카리 상품을 장바구니에 담는다.
2. `/order?items=…`에서 주문한다.
3. 확인 창 없이 결제창이 열리는지 본다.
4. 결제창 금액이 주문서의 「결제 예정 금액」과 같은지 본다.
5. 테스트 카드로 결제한다.
6. `/order/<id>`가 「결제 완료」인지 본다.
7. 주문 번호(앞 8자리)가 어드민 주문 목록과 같은지 본다.

## 2. 장바구니 주문: 가격이 오른 경우

1. 장바구니에 담은 상품의 `external_items.price`를 DB에서 실제보다 낮게 바꾼다.
2. 주문서를 새로 연다(낮은 가격이 보인다).
3. 주문 버튼을 누른다.
4. 「결제 전에 바뀐 상품이 있어요」 창이 뜨는지 본다.
5. 창의 새 합계가 실제 가격 기준인지 본다.
6. 「바뀐 가격으로 결제하기」를 누른다.
7. 결제창 금액이 새 합계와 같은지 본다.

## 3. 장바구니 주문: 가격이 내린 경우

1. `external_items.price`를 실제보다 높게 바꾼다.
2. 주문 버튼을 누른다.
3. 확인 창 없이 결제창이 열리는지 본다.
4. 결제창 금액이 실제(낮은) 가격 기준인지 본다.

## 4. 품절·확인 불가

1. 품절된 메루카리 상품을 장바구니에 넣어 둔다(담은 뒤 품절된 상품).
2. 주문 버튼을 누른다.
3. 창에 「품절됐거나 판매가 끝났어요」가 보이고, 진행 버튼 대신 「장바구니로 가기」가 있는지 본다.
4. 결제창이 열리지 않았는지 본다.
5. 파싱이 안 되는 상황(마켓 차단)은 `fetched_at`을 20분 전으로 바꾸고 파서를 끊어 본다. 「지금 가격을 확인하지 못했어요」가 보여야 한다.

## 5. 오래된 대기 주문 재결제

1. 주문만 만들고 결제창을 닫는다.
2. 15분 넘게 기다린다(또는 `proxy_orders.created_at`을 20분 전으로 바꾼다).
3. 열린 결제창이 없는지 확인한다(30분 지나면 Stripe가 닫는다).
4. 가격을 바꾸지 않았으면 「다시 결제」로 결제창이 열리는지 본다.
5. 가격을 올려 두었으면 창에 「이 주문은 결제하지 않았어요」 안내가 뜨는지 본다.

## 6. 국경 간 직거래

1. 일본 판매자 상품(국경 간 허용)을 한국 계정으로 산다.
2. 결제창 금액이 「상품가 + ¥900」의 원화 환산인지 본다.
3. 개발자 도구로 `/api/checkout` 본문에 `intlShippingFee: 0` 또는 `99999`를 넣어 보낸다.
4. 금액이 3번과 같게 「상품가 + ¥900」인지 본다.
5. 같은 나라 거래와 만남 거래는 배송비가 0인지 본다.

## 7. 환불

1. 1번에서 결제한 주문을 어드민에서 환불한다.
2. Stripe 대시보드에 환불이 1건 생겼는지 본다.
3. `/order/<id>` 환불 줄이 보이는지 본다.

## 8. 오류 문구

1. 일본어 계정으로 2·4번을 반복한다.
2. 창과 오류 문구가 전부 일본어인지 본다.
3. 로그아웃 상태에서 `/api/order`를 부르면 401과 언어에 맞는 문구가 오는지 본다.
