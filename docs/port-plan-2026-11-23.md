## 2. 제외 (이유)
바우처 충전(1회 결제라 쓸 곳 없음) · 멤버십·등급 할인(정책 없음, 신뢰온도가 대신) · 추천인(적립 수단 없음) · 야후 자동입찰(즉시구매 대행) · 3PL·창고·합배송(사업자용) · 홍보 레이더·셀러 도구·캠페인·블로그 CMS · 메루카리 협상 대행(가격제안·자동번역이 대신) · AI 상담(LLM 미사용 결정) · 알림톡·메일 템플릿(발송 계약 없음) · 직원 메뉴 권한(DB 못 막음) · 요율표·관세율 표(금액 정본 이중화) · 미결제 크론(10분 만료 있음) · 블랙리스트·IP·휴면(정지로 충분).

## 3. DB (0025~0029, 순서대로 적용)
공통: 돈 테이블은 직접 쓰기 revoke, SECURITY DEFINER RPC로만. 관리자 판정은 `is_admin_user()`. 기존 함수는 시그니처 유지 `create or replace`.

### 0025_refunds_admin_cancel.sql
- `admin_actions(id bigint identity pk, admin_id uuid → profiles, action text, target_type text, target_id text, detail jsonb default '{}', created_at)`. RLS select `is_admin_user()`. 쓰기는 내부 함수 `log_admin_action(action,target_type,target_id,detail)`만.
- `transactions` + `paid_krw integer`, `cancel_reason text`. `proxy_orders` + `paid_krw integer`. `proxy_requests` + `cancel_reason text`, `cancel_requested_at timestamptz`, `refund_amount integer`.
- enum `refund_status('pending','done','failed')`. `refunds(id uuid pk, kind text check in ('tx','proxy_order'), transaction_id, proxy_order_id, proxy_request_id, user_id not null, payment_key text not null, amount int >0, currency currency_code, amount_krw int null(=전액), is_full bool, reason text not null, status default 'pending', attempts int default 0, last_error text, created_by uuid, created_at, done_at)`. unique (transaction_id) where kind='tx'; unique (proxy_request_id) where not null. RLS select 본인 또는 관리자, 쓰기 revoke.
- RPC: `resolve_dispute(uuid, tx_status, text)` 재정의(cancelled+결제키 → refunds pending, 로그) · `admin_cancel_transaction(p_tx_id uuid, p_reason text)`(paid·shipped_to_center·center_received만, 재판매 복귀는 paid에서만, 환불 행) · `admin_complete_transaction(p_tx_id uuid, p_note text)`(delivered→completed) · `admin_cancel_proxy(p_id uuid, p_reason text, p_refund_amount int default null) returns jsonb`(주문 for update, 요청 cancelled, 환불액 = 취소 전 주문 금액 − 남은 항목으로 재계산(`proxy_customs` 재사용), 남은 항목 없으면 미환불 잔액 전부, 상한 total − 기존 환불 합, 결제키 없으면 `{refund:null}`) · `request_proxy_cancel(p_id uuid, p_reason text)`(본인, paid만, cancel_requested_at 기록) · `refund_mark(p_id uuid, p_ok boolean, p_error text, p_amount_krw int)`(service_role 전용).

### 0026_payouts.sql
- enum `payout_status('requested','sent','rejected')`. `payout_accounts(user_id, currency, bank_name, account_number, account_holder, updated_at, pk(user_id,currency))` RLS 본인 전부·관리자 select. `payouts(id, user_id, currency, amount>0, bank_name, account_number, account_holder(스냅샷), status default requested, admin_note, processed_by, requested_at, processed_at)` unique (user_id,currency) where status='requested'. `seller_ledger(id identity, user_id, currency, amount int, kind check in ('sale','payout_hold','payout_release','adjust'), transaction_id, payout_id, memo default '', created_by, created_at)` unique (transaction_id) where kind='sale'. select 본인/관리자, 쓰기 revoke.
- 트리거 `transactions_credit_sale`: completed로 바뀌고 결제키 있으면 sale 행(item_price − platform_fee), on conflict do nothing.
- `seller_balances()` · `request_payout(p_currency, p_amount)`(advisory lock, 계좌·잔액 확인, payouts + payout_hold(−)) · `admin_process_payout(p_id, p_sent bool, p_note)`(rejected면 payout_release(+), 로그) · `admin_adjust_seller_ledger(p_user, p_currency, p_amount, p_memo 필수)` · `admin_seller_liability()`.

### 0027_notifications.sql
- `notifications(id identity, user_id → profiles on delete cascade, kind text, ref_type text, ref_id text, data jsonb default '{}', read_at, created_at)` index (user_id, created_at desc). RLS select 본인, grant update(read_at)만, insert revoke.
- 문구는 DB에 없음: 앱이 `kind` → i18n `notif.<kind>`. 내부 함수 `notify(p_user,p_kind,p_ref_type,p_ref_id,p_data)`를 트리거가 호출.
- 트리거: transactions 상태(tx_paid 판매자, tx_shipped 구매자, tx_delivered·tx_completed 판매자, tx_cancelled 양쪽, tx_disputed 상대) · proxy_requests(proxy_quoted, proxy_purchasing, proxy_center, proxy_shipped, proxy_delivered, proxy_cancelled) · support_tickets→answered(support_answered) · refunds→done(refund_done) · payouts→sent/rejected(payout_sent, payout_rejected) · offers(offer_received, offer_accepted, offer_declined) · listings 가격 인하(wish_price_drop, 찜한 사람). refunds/payouts 트리거는 해당 테이블이 있을 때만(0027은 0025·0026 뒤 적용).
- RPC `unread_notifications() returns int`, `mark_notifications_read(p_ids bigint[] default null)`.

### 0028_addresses_account.sql
- `addresses(id, user_id → profiles cascade, label default '', name, phone, postal, address, note default '', pccc check null or ~ '^P[0-9]{12}$', is_default bool, created_at)` unique (user_id) where is_default. RLS 본인 CRUD, 관리자 select. 1인 10개 제한 트리거. 백필: profiles.ship_name 있는 회원 → 기본 배송지 1행. `proxy_orders` + `ship_pccc text`.
- `set_default_address(p_id)`(기본 변경 + profiles.ship_* 복사) · `attach_order_pccc(p_order_id, p_address_id)`(본인 pending_payment 주문에 스냅샷) · `account_blockers() returns jsonb`(진행 거래, 진행 대행 approved~delivered, 미완료 환불, 0 아닌 정산 잔액, 신청 중 출금) · `deactivate_my_account(text)` 재정의(차단 사유 있으면 raise 'blocked', 없으면 기존 + requested·quoted 대행·대기 제안 취소).

### 0029_content.sql
- `banners(id, audience check in ('KR','JP','ALL'), image_path, alt_ko, alt_ja default '', link_url, starts_at, ends_at, sort_order default 0, is_active default true, updated_by default auth.uid(), created_at, updated_at, check 기간)`. `notices(id, published_on date default current_date, title_ko, title_ja, body_ko, body_ja, pinned default false, is_published default true, created_at, updated_at)`. RLS 공개 select(켜짐·기간 안 / 게시됨), 관리자 전부, 쓰기 관리자. storage 버킷 `banners`(공개 읽기, 관리자 쓰기, 5MB, jpeg/png/webp). notices 시드: `lib/notices.ts` 1건.

## 6. 위험
1. 0025~0029 미검증. 재개 후 순서대로 적용하고 `begin … rollback` 검증 전에는 실환불을 켜지 않는다.
2. 환불은 「DB 먼저, 토스 나중」.
3. 부분 환불은 `quote_item_price` 기준 → 관리자 화면에 금액 미리 보여 주고 상한 안에서 수정.
4. 구매확정 안 누르면 판매 대금 적립 안 됨 → 관리자 강제 확정. 자동 확정은 P2. 과거 완료 거래 정산 백필 없음.
5. `transactions`에 구매자 배송지 스냅샷 없음(추정). 묶음 C 착수 전 `app/transactions/[id]/page.tsx`, `app/admin/center/page.tsx`, 0023 확인.
